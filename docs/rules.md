## Geometry

- **R1 · Millimetres.** All geometry is in mm — ring radii, hand lengths, everything. Points appear only at render time (`MM = 72 / 25.4`) and when reading imported files (`MM_PER_PT`). The web version's unit box changes what the window shows and takes, never what is stored.
- **R2 · Clock angles.** 0° = 12 o'clock, growing clockwise. DrawBot turns counter-clockwise, so rotations are negated in one place: `place()`.
- **R3 · Draw upright, then place.** A shape is drawn at the origin pointing outward (+y), then moved to its radius and turned to its angle.
- **R4 · Filled shapes only.** Everything that can be exported is a filled path — no strokes. Bands are sectors (two arcs and two lines) or two circles subtracted; hollow shapes are an outline minus an inset; imported strokes are outlined.
- **R5 · Guides and backdrop are preview-only.** Never exported.
- **R6 · Geometry is a function of settings.** Parts 1–3 of `archive/drawbot/dial.py` (settings, geometry, drawing) never touch the interface; they take the settings dictionary `S` and return shapes. That is what makes them testable off-Mac.
- **R26 · One scene.** Export and every preview draw from `scene()` (part 3). The only differences allowed are preview-only: guides, backdrop, the canvas drawing guides in screen points, and (web version, beta 4.38) **shadows**, drawn by `draw_shadows()` in `app.js` from the scene's items. None of them reaches an export (R5).
- **R23 · Imported files (SVG, PDF, AI).** Drawn pointing up (12 o'clock); the artboard's centre is the anchor — a hand's pivot, a marker's centre. Only the first page counts. Fills are ink; plain white fills (gray 1, RGB 1 1 1, CMYK 0 0 0 0) cut; strokes become outlines (R4); clipping is ignored; text, images and gradients are skipped and reported in the Export log. Colours set through spot/indexed spaces (`scn`) count as ink. AI files must be saved with "Create PDF Compatible File".

## Settings

- **R7 · Every setting has a starting value** in one of three places. `DEFAULTS`: the dial, hands, date, output and interface, with prefixed keys — `dial_`/`margin` · `c_` colour · `ha_` hands · `da_` date · `out_` output · `ui_` interface. `RING_BASE`: every key a ring can have; every ring carries all of them, so changing a ring's kind keeps its settings. `HAND_BASE`: one hand's keys. Keys inside a ring or a hand have no prefix.
- **R8 · Never rename a setting key** without a migration: saved presets and the last session use these names. `from_beta1()` converts beta 1.0 settings; `fresh_settings()` runs it automatically.
- **R9 · Popups store an index**, never the label text. Lists of choices (`LABEL_SETS`, `KINDS`, `HAND_SHAPES`…) only ever grow at the end.

## Type

- **R10 · Text always goes through DrawBot's `FormattedString`** and becomes outlines (`BezierPath.text`), so font, tracking, features, axes and language all reach the vectors. The export option *live text* draws the same `FormattedString` as text instead, placed from the outlines' bounds (`numeral_setup`, `path_letters`, `text_centre` are shared) so both land in the same place; cuts become clipping masks. Preview and production masks are always outlines.
- **R11 · Tracking is in 1/1000 em** (Illustrator's unit), converted to absolute only at drawing time.
- **R12 · OpenType features store only what differs from the font's default** (kern, liga, calt… are on by default).

## Interface

- **R13 · Only what ships with DrawBot 3.132:** vanilla 0.5.0, DrawBot itself, and Apple's frameworks through DrawBot's PyObjC (AppKit, Quartz, CoreText, Core Animation — `archive/drawbot/dial.py` already uses the first three directly). Read the source before using a call; `archive/drawbot/tools/vanilla-0.5.0-api.json` lists every vanilla class signature and method. APIs from macOS 14 are allowed with a fallback (R17): both of Okay's Macs run macOS 15 (4 Oct 2026). *Reworded 4 Oct: it said "only vanilla and DrawBot", which the code had already outgrown.*
- **R14 · No vanilla `Tabs` around auto-layout content** — it collapses. Use segmented switchers (sections, hands) or one scrolling list (R24).
- **R15 · A number has three ways in — type it, step it, sweep it —** kept in sync, the same in every form. Typing past the slider's range extends it. A row's **form** says which of the three it shows; the others are one press away, in the number's popup. The forms are listed here, so a new form is a new line in this list, not an exception (Okay, 16 Oct 2026: "r15 sounds good"; until then R15 carried two exceptions, both from 13 Oct 2026):
  - **A · Full row**: label · slider · typed field · stepper. The starting form, and the one for numbers explored by sweeping (radius, size, length). A **quiet look** of its number part is for the side rows beside a hand's detail box: the number with no box, grey until it changes, a compact ± beside it (Okay, 16 Oct 2026; build list #250). Until #250 is built those rows keep the **number box** of beta 4.25 (the same four parts, the stepper tiny until the number is pressed); it goes when #250 comes.
  - **B · Quiet row**: label · the number with a compact ± and no slider; the slider, the typed field and the rest stand in the popup (a click on the name or the number; on a phone, anywhere on the line). For numbers that are set more than swept: counts, angles, Positions, Nudge, a window's width and height. *Not built yet: #249, #251, #252, #265.*
  - **C · Value button**: in a line that sums a thing up (the selected ring's line) a small drawing stands for the number and its value is read beside it; a click opens the number's popup, pressing and moving changes the value (beta 4.7; the popup is the button's tag grown, beta 4.12).
  - **The popup** (one for every form, build list #249): the number's name, the slider on top, the value in a pill, a row of round − and + under them, all inside a 2 px dark-grey frame on a ground darker than the pane's; its slider's thumb larger by a fifth. *Not built yet.*
- **R16 · Rows that don't apply are hidden**, not disabled.
- **R17 · No dead ends.** Every risky call has a fallback or reports to the Export log — never fails silently.
- **R22 · Keep every control's Python object alive.** vanilla stores a control's callback on the Python object (`_target`); Cocoa controls don't retain their target; `GridView` keeps only the Cocoa view. A control that exists only inside a grid loses its callback as soon as the building function returns: popup items turn grey, clicks do nothing. Store controls on the tool (`self.keep`, a binding, or a named attribute). Found 4 Oct 2026 (beta 1.0.1).
- **R24 · A scrolling form** is a vanilla `Group` laid out with auto layout, inside a flipped document view (`DialToolFlippedView`, looked up before it is defined so ⌘R again works), pinned to the scroll view's clip view at top, leading and trailing — never bottom, so the content decides the height. A view with no size of its own inside a `GridView` cell (a `List`) needs an explicit width and height.
- **R27 · Our own Cocoa classes** have one name per contract, ending in a number (`DialToolCanvasView1`), are looked up with `objc.lookUpClass` before being defined (a process can't define a class twice; ⌘R runs the script again), and only pass events on to Python. Change what a class must do → a new number. (`DialToolFlippedView` predates the numbering; R24.)
- **R28 · Nothing renders inside a control's callback.** Callbacks change settings and call `render()`, which only asks for a frame; the frame clock (`Clock`, `_frame`) draws, at most once per display frame.

- **R30 · The web version** (`web/`) is where the tool is built. **`archive/drawbot/dial.py` is frozen** (Okay, 12 Oct 2026: "Do not work on dial.py anymore, we're on github"): it is not edited, and new settings keys go into `web/src/geometry.js` only. The keys the two share keep their names (R8), so an old settings file still opens in both; a key only the web version knows is ignored by `dial.py`. The web version builds to **one file** with nothing fetched at run time; its two engines are pinned in `web/package.json` (PathKit — Skia's shape combining; HarfBuzz — text). R1–R6, R9–R12, R15–R17, R26 and R28 apply to it as written; R13, R14, R22, R24 and R27 are about DrawBot's window only. The parity test (`web/test/parity.py`) still compares the shared geometry with `dial.py`; a web-only feature is outside it. *Added 11 Oct 2026; reworded 12 Oct.*

- **R31 · A dial's link is for sharing a dial now; a settings file is for keeping one** (web version). A link carries only what differs from the starting values (`lean()` in `web/src/geometry.js`), packed and written in capitals and digits — link scheme 2 since beta 4.43 (build list #278; until then scheme 1, base 64 with "~"; `LINK_KEYS`, the key table, only grows, checked by `web/test/linktrip.mjs`). **Old links may die** (Okay, 16 Oct 2026: "previous links may die, replace the system"): the starting values (`DEFAULTS`, `RING_BASE`, `HAND_BASE`, `WINDOW_BASE`, the starting rings and hands) may change when a change needs it. Whenever a change would make an existing link draw something else — a starting value, the key table, the alphabet — the scheme number goes up, and a link of another scheme is not read: the tool opens the opener and says, on the preview and in the Export log, that the link was made by an older Dial Tool (R17: no silent dead end, and never a dial quietly drawn wrong). A new key whose starting value draws what was drawn before needs no new scheme. Keys are never renamed (R8), so a settings file, which holds every value, keeps opening. When the scheme changes, everything in the repo kept as a link is written again from its settings (the Gallery: `node gallery.mjs`; the examples: `node examples.mjs`); **the live guide's links die until the guide is rebuilt**, which happens on Okay's word only (R25). *Added 11 Oct 2026; replaced 16 Oct 2026. Until then the starting values were frozen for good and old links were kept, with three waivers (the centre hole, 14 Oct; shadows and guides, 15 Oct; brief §4). The rewrite proposed earlier on 16 Oct (golden links, a list of waivers) was not taken.*

- **R32 · The web version's stylesheet** is the folder `web/src/css/`, one file per part, joined by `build.mjs` in the order of their names; each file is one cascade layer, and the layers come in this order: tokens · base · controls · panel (files 4a–4h: frame, lines and tabs, rows, hands, colour, rings, fonts, gallery) · **chosen** (what is switched on, picked or open is ink with paper words — one rule for every control, in a layer of its own so nothing earlier can undo it) · preview · bar · narrow. A value (colour, size, measure) is written once, as a token in `:root`, and used by name; a new value is a new token with a comment saying what it is. **Every space is a step of the unit** (`--u1` half a unit … `--u8` four units; `--unit` itself; `--air`); a line is `--hair`, `--thick` or `--triple`; pure white and black are `--white` and `--black`; hex is written short where it can be. A rule goes in the layer of the part it styles and never undoes another part's rule; no `!important`; no negative margin to escape a padding, and no exception (the `--frame-out` exception is gone since beta 4.35.14, Okay, 14 Oct 2026: "lock it down"). **A framed thing** — a ring row, the font box — stands between the pane's lines, from the labels' line to the pane's right line; inside, `--frame-pad` keeps what is in it off the frame (the eye at the left of a ring row, the steppers and Change… at the right of the font box, whose sliders give up that room). A number's row lays its tracks out in full (`--num-columns`: columns, gaps, then the two tiles) rather than nudging its field and stepper. A plain `button` has no look: its class says what kind it is; a tab (`.tab`) draws itself in two clipped layers and cuts its own top corners. Sizes of type: the `--t-` tokens only (four, and `--t-xxs`, 10, and one for the bottom bar alone, `--t-time`, 17, the time — Okay, 14 Oct 2026, 23:55, on branch `try/shadows`; the smallest, for the font sheet's legend and the font box's quiet buttons, Lang. and Change…, which are three quarters of a button, `--control-s` — Okay, 14 Oct 2026) — and `--t-pixel` (8) for the pixel font, Silkscreen, which sets the tiny numbers inside small drawings (a value button, the numerals picture) and the **stickers**, and is used at that size or its double, 16 (a sticker in a font box), never between — one exception: the font sheet's legend (title and stickers), at 12 (Okay, 14 Oct 2026: "75 % size", then ".5 more size on all silkscreen"; on a 2× screen, as the iPad and the Macs are, its dots still fall on the screen's) — at `--pixel-ink` (70 %) of its colour (Okay, 13 Oct 2026; the double since beta 4.31) — but the "1×" over the bottom bar's speed ball, in the ball's own colour (Okay, 15 Oct 2026: "same color as the ball"). A short label in a box of its own is listed in `INKED` (`web/src/ink.js`): it gets proportional figures and is centred on its ink, measured, never nudged by hand (design canon §2; Okay, 14 Oct 2026); numbers that change in place stay tabular. A control smaller than a row's height goes into the *reach* rule (controls layer), so a finger can press it from just outside its edge. **A change to the stylesheet that must not change the look is proved** with the look-check, `web/test/same.mjs`: save the look before (`node test/same.mjs save`), compare after; it reads the computed style of every element in 447 states and prints every difference. **Special places** (Okay, 16 Oct 2026: "r32 is fine"; special places "may happen sometimes"). A value may leave the scale, or a part the rules above, only as a **special**: a named token in one labelled block of `1-tokens.css` (`/* specials */`), with Okay's words and the date beside it, used by name — never a bare number in a rule. `!important` and negative margins stay banned: there is no special for them. The layout check (#188) will read the block, so anything off the scale that is not in it fails; the block is looked through at each release (how many, still wanted?). The block stands at the end of `:root` in `1-tokens.css` (beta 4.42, #290), in two groups: the ones Okay asked for (`--control-s`, `--t-xxs`, `--t-time`, the pixel font's 12, the bar's pixel labels and the unit box's word at full strength, the pop-out's chip gap, the speed box's padding, the Gallery pill's lift), and the ones found off the scale with no figure from him (#294). The grid's own measures (`--margin`, `--eye`, `--gap`, `--col`) and the sizes of things are not specials. *Added 12 Oct 2026, with the review Okay asked for; rewritten 13 Oct 2026, night, with beta 4.35; special places added 16 Oct 2026.*

- **R33 · Icons** (web version; canon: `docs/design.md` §9). Every icon is drawn in the icon block at the top of `web/src/app.js`, at the size it is shown (viewBox = size on screen; the hand tiles alone at ×2). Every stroked line uses one of the four widths there, `LINE` 1.5 · `SLANT` 1.5625 · `CURVE` 1.625 · `DENSE` 1.25, chosen by what the line is (straight · slanted · curved · crowded), or a pictured width listed in `web/icons/check.mjs`; a quiet sign (Okay's choice, e.g. the rename box) is `DENSE` with its box's corners `DENSE + 1/8`; a dashed ring ends its dashes square, every other line round; a box with round corners is drawn with `box()`; a `LINE`'s level and upright runs sit on quarter points. Rings, frames and outlines inside an icon are icon lines and weigh the same as the rest; a stylesheet border is never used for a line that is part of a sign. A new or changed icon goes through the pipeline: `web/icons/fit.mjs` (on the grid), `web/icons/check.mjs` (the rules; in `npm test`, must pass), `web/icons/look.py` (how heavy it looks: within 6 % of a straight `LINE`, or a reason), and a look at `web/icons/out/sheet.png`. *Added 14 Oct 2026 (beta 4.36), Okay: "Let this knowledge of good and proper icon making be canon. This pipeline for upcoming icons."*

## Process

- **R18 · Simplest approach that works** (Occam). No new feature without Okay asking.
- **R19 · Test before handing over.** Geometry: `archive/drawbot/tools/test_harness.py`, and look at the contact sheet. Interface: `archive/drawbot/tools/ui_smoke.py` must pass. Web version: `cd web && npm test` must pass (it includes the icon check, R33), and look at `web/test/out/sheet.png`, the screenshots and, after an icon change, `web/icons/out/sheet.png`.
- **R20 · Third attempt at the same fix → stop and ask.** The first assumption was probably wrong.
- **R21 · Measure, don't estimate** — sizes and timings come from real renders.
- **R25 · The guide follows the app** (`guide/`, by `guide/PLAN.md`; reworded 15 Oct 2026, when the 4.36.1 lock ended). Its pictures are made by script from the current app, never drawn; every "do X and Y happens" sentence has a scripted check that must pass. **It is rebuilt only when Okay asks** (`bash guide/make.sh`; Okay, 16 Oct 2026: "decouple the guide creation from each build, it's hand generated every once in a while by triggered me"): an app release does not touch it, and the live guide names the version it was made on; the picture diff then shows what changed since the last guide. Never type a value into the guide that a picture or a check doesn't use. Page design follows `guide/notes-okay.md` and the design canon (R29). *Until 15 Oct: the DrawBot guide, built by `tools/make_guide.py` from `archive/drawbot/dial.py`.*
- **R29 · `docs/design.md` is the design canon** for anything shown that isn't a dial: type, grid, colour, pictures, redrawn controls, writing. Follow it; when a new need doesn't fit, change the canon first, then the page.
