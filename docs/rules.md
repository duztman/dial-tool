# Dial Tool — rules

Standing rules for the web version (`web/`), the tool since 12 Oct 2026. Check code against these in reviews; cite them by number. Numbers are never reused: the DrawBot version's own rules (R13, R14, R22, R24, R27) are in `archive/drawbot/rules-drawbot.md`. How a rule came to be is in `docs/changelog.md` and the repo's history, not here.
*Last updated 19 Oct 2026 (beta 4.89: R16 takes in empty panes; R34, no band-aids. Beta 4.88.1: R19, two sizes of check. Beta 4.88: R26's X-ray; R31: link scheme 3. Beta 4.87: web wording throughout, the DrawBot rules archived, R15's form A2 retired).*

## Geometry

- **R1 · Millimetres.** All geometry is in mm — ring radii, hand lengths, everything. Points appear only in a file (`MM = 72 / 25.4`, `output.js`). The unit box changes what the window shows and takes, never what is stored.
- **R2 · Clock angles.** 0° = 12 o'clock, growing clockwise. The drawing turns the other way, so rotations are negated in one place: `place()` in `geometry.js`.
- **R3 · Draw upright, then place.** A shape is drawn at the origin pointing outward (+y), then moved to its radius and turned to its angle.
- **R4 · Filled shapes only.** Everything that can be exported is a filled path — no strokes. Bands are sectors (two arcs and two lines) or two circles subtracted; hollow shapes are an outline minus an inset.
- **R5 · Guides and backdrop are preview-only.** Never exported.
- **R6 · Geometry is a function of settings.** `geometry.js` (settings, geometry, drawing) never touches the window; it takes the settings `S` and returns shapes. That is what makes it testable without a window (`web/test/parity.py`, `labels.mjs`, `linktrip.mjs`).
- **R23 · Imported files (SVG, PDF, AI)** — not built in the web version (build list #50); when they are: drawn pointing up (12 o'clock); the artboard's centre is the anchor — a hand's pivot, a marker's centre. Only the first page counts. Fills are ink; plain white fills cut; strokes become outlines (R4); clipping is ignored; text, images and gradients are skipped and reported in the Export log.
- **R26 · One scene.** Export and every preview draw from `scene()` (`geometry.js`). The only differences allowed are preview-only: guides, backdrop, the canvas's guides in screen points, **shadows** (`draw_shadows()` in `app.js`, from the scene's items), **X-ray** (the windows' discs whole, in a stack by depth with the selected one on top, each layer fainter than the one above; and the discs' dashed edges), a **case** round the dial and its **strap** or bracelet (`bezels.js`; the view fits the dial, never the case), and the **Tiny Preview**'s window (drawn from an export). None of them reaches a file (R5).

## Settings

- **R7 · Every setting has a starting value** in one of four places. `DEFAULTS`: the dial, hands, date, output and interface, with prefixed keys — `dial_`/`margin` · `c_` colour · `ha_` hands · `da_` date · `out_` output · `ui_` interface · `gd_` guides · `sh_` shadows. `RING_BASE`: every key a ring can have; every ring carries all of them, so changing a ring's kind keeps its settings. `HAND_BASE`: one hand's keys. `WINDOW_BASE`: one window's. Keys inside a ring, a hand or a window have no prefix.
- **R8 · Never rename a setting key** without a migration: settings files and the last session use these names. `from_beta1()` converts beta 1.0 settings; `fresh_settings()` runs it. A key nothing reads any more stays in `DEFAULTS` with a comment, so an old file still opens.
- **R9 · Popups store an index**, never the label text. Lists of choices (`LABEL_SETS`, `KINDS`, `HAND_SHAPES`…) only ever grow at the end.

## Type

- **R10 · Text is shaped by HarfBuzz and becomes outlines** (`geometry.js`), so font, tracking, features, axes and language all reach the vectors. The export option *live text* writes the same shaped text as text instead, placed from the outlines' bounds, so both land in the same place; cuts become clipping masks. Preview and production masks are always outlines.
- **R11 · Tracking is in 1/1000 em** (Illustrator's unit), converted to absolute only at drawing time.
- **R12 · OpenType features store only what differs from the font's default** (kern, liga, calt… are on by default).

## Interface

- **R15 · A number has three ways in — type it, step it, sweep it —** kept in sync, the same in every form. Typing past the slider's range extends it. A row's **form** says which of the three it shows; the others are one press away, in the number's popup. The forms are listed here, so a new form is a new line in this list, not an exception (Okay, 16 Oct 2026: "r15 sounds good"):
  - **A · Full row**: label · slider · typed field · stepper. The starting form, and the one for numbers explored by sweeping (radius, size, length). **One number box** in every form (Okay, 18 Oct 2026, 21:20: "This version of boxes win … these replace all"): the value's box, then − and + in theirs, all touching, one hairline of the rule's grey; the signs drawn, 12 across in their cell (9 in a narrow box). Beside a hand's detail box, in a quiet row (form B) and in Positions the same box, narrower. Under a finger (Okay, 18 Oct 2026, 22:35) the row's slider and its name open the controller, tapped or slid; the field takes typing and − + step in place, as with a mouse. A **chevron box** (a value chosen from a menu: Count, Every) is the value's box and one ⌄ box, same style.
  - **B · Quiet row**: label · the number box and no slider; the slider, the typed field and the rest stand in the popup (a click on the name or the number; on a phone, anywhere on the line). For numbers that are set more than swept: counts, angles, Positions, Nudge, a window's width and height. Declared on a row as `quiet`: a side row whose slider is not shown (Positions\' five numbers, #251; a ring\'s Clearance). Two numbers that belong together (a window\'s width and height) are two full rows linked by a **LINK pill** on the line between them (#358): linked, changing one keeps their ratio.
  - **C · Value button**: in a line that sums a thing up (the selected ring's line) a small drawing stands for the number and its value is read beside it; a click opens the number's popup, pressing and moving changes the value .
  - **The popup — the controller** (one for every form, build list #249; Okay's drawing `controller 2.svg`, 18 Oct 2026, #330): one dark square, see-through (85 %), holding three things one height: the value in bold on a grey pill, the slider in a white pill, and − and + as two dark discs with white square-ended signs at its foot, one at each side; at three quarters of the drawing's size (Okay, 19 Oct 2026: "Size 75%"). **No name** (Okay, 18 Oct 2026: "No name necessary, preview shows what's changing anyway"): a row's menu (the numerals' anchor) stays on the row. It stands where the finger pressed, the knob under it, over everything; it comes at once and, 1.2 s after its last use, fades away; a press elsewhere, Escape or Enter put it away at once. A full row's name opens it too; a press on the name moved sideways drags the value (#170); the finger that opens it goes on sliding it. A linked pair's LINK disc stands between − and + (#358). While a number is slid (in the popup, or a name or value button dragged) the guides show as set, even with Guides off; a numeral being nudged hides them (#252).
- **R16 · What can't be used is hidden, not disabled** — rows that don't apply, and a pane whose rows all don't apply goes with them, heading and all (Okay, 19 Oct 2026: "We don't need to see a header we do not have the interaction with"; `sync_rows()` in `app.js` hides such a pane, so no row or heading needs a condition of its own for it). One exception: a control that can't act just now but is worth knowing is there shows inactive — Undo and Redo with nothing to undo or redo ("Only inactive if unable to do anything but nice to know it's there: redo qualifies").
- **R17 · No dead ends.** Every risky call has a fallback or reports to the Export log — never fails silently.
- **R28 · Nothing renders inside a control's handler.** Handlers change settings and call `render()`, which only asks for a frame (`requestAnimationFrame`); `frame()` draws, at most once per display frame.
- **R30 · The web version** (`web/`) is the tool. **`archive/drawbot/dial.py` is frozen** (Okay, 12 Oct 2026: "Do not work on dial.py anymore, we're on github"): it is not edited, and new settings keys go into `web/src/geometry.js` only. The keys the two share keep their names (R8), so an old settings file still opens in both; a key only the web version knows is ignored by `dial.py`. The web version builds to **one file** with nothing fetched at run time; its two engines are pinned in `web/package.json` (PathKit — Skia's shape combining; HarfBuzz — text). The parity test (`web/test/parity.py`) still compares the shared geometry with `dial.py`; a web-only feature is outside it.
- **R31 · A dial's link is for sharing a dial now; a settings file is for keeping one.** A link carries only what differs from the starting values (`lean()` in `geometry.js`), packed and written in capitals and digits — link scheme 3 since 4.88 (`LINK_SCHEME`; `LINK_KEYS`, the key table, only grows, at its end, and is checked against `web/test/link-keys.json` by `linktrip.mjs`). **Old links may die** (Okay, 16 Oct 2026: "previous links may die, replace the system"): the starting values (`DEFAULTS`, `RING_BASE`, `HAND_BASE`, `WINDOW_BASE`, the starting rings and hands) may change when a change needs it. Whenever a change would make an existing link draw something else — a starting value, the key table, the alphabet — the scheme number goes up, and a link of another scheme is not read: the tool opens the opener and says, on the preview and in the Export log, that the link was made by an older Dial Tool (R17: no silent dead end, and never a dial quietly drawn wrong). A new key whose starting value draws what was drawn before needs no new scheme. Keys are never renamed (R8), so a settings file, which holds every value, keeps opening. When the scheme changes, everything in the repo kept as a link is written again from its settings (the Gallery: `node gallery.mjs`; the examples: `node examples.mjs`; the opener's link in `opener.js`); the live guide's links die until the guide is rebuilt, on Okay's word only (R25).
- **R32 · The web version's stylesheet** is the folder `web/src/css/`, one file per part, joined by `build.mjs` in the order of their names; each file is one cascade layer, and the layers come in this order: tokens · base · controls · panel (files 4a–4h: frame, lines and tabs, rows, hands, colour, rings, fonts, gallery) · **chosen** (what is switched on, picked or open is ink with paper words — one rule for every control, in a layer of its own so nothing earlier can undo it) · preview · bar · narrow. A value (colour, size, measure) is written once, as a token in `:root`, and used by name; a new value is a new token with a comment saying what it is. **Every space is a step of the unit** (`--u1` half a unit … `--u8` four units; `--unit` itself; `--air`); a line is `--hair`, `--thick` or `--triple`; pure white and black are `--white` and `--black`; hex is written short where it can be. A rule goes in the layer of the part it styles and never undoes another part's rule; no `!important`; no negative margin to escape a padding, and no exception (Okay, 14 Oct 2026: "lock it down"). **A framed thing** — a ring row, the font box — stands between the pane's lines, from the labels' line to the pane's right line; inside, `--frame-pad` keeps what is in it off the frame (the eye at the left of a ring row, the steppers and Change… at the right of the font box, whose sliders give up that room). **A heading that carries controls on its line** (a window's places, its shapes) gives them a unit over and under, as the tiles in a row get, and grows to hold them; its title keeps the place it has on every heading, the same gap over it (Okay, 16 Oct 2026: "These rows are allowed height growth now… appropriate vertical padding like all the rows"; "top gap stays same"). A number's row lays its tracks out in full (`--num-columns`: columns, gaps, then the two tiles) rather than nudging its field and stepper. A plain `button` has no look: its class says what kind it is; a tab (`.tab`) draws itself in two clipped layers and cuts its own top corners. Sizes of type: the `--t-` tokens only (four, and `--t-xxs`, 10, and one for the bottom bar alone, `--t-time`, 20, the time — Okay, 14 Oct 2026, 23:55; the smallest, for the font sheet's legend and the font box's quiet buttons, Lang. and Change…, which are three quarters of a button, `--control-s` — Okay, 14 Oct 2026) — and `--t-pixel` (8) for the pixel font, Silkscreen (and, for the bar's time and AM · PM alone, Dial Time — Barlow Condensed Light, packed, `--time-face`, #284), which sets the tiny numbers inside small drawings (a value button, the numerals picture) and the **stickers**, and is used at that size or its double, 16 (a sticker in a font box), never between — one exception: the font sheet's legend (title and stickers), at 12 (Okay, 14 Oct 2026: ".5 more size on all silkscreen"; on a 2× screen, as the iPad and the Macs are, its dots still fall on the screen's) — at `--pixel-ink` (70 %) of its colour (Okay, 13 Oct 2026) — but the "1×" over the bottom bar's speed ball, in the ball's own colour (Okay, 15 Oct 2026: "same color as the ball"). A short label in a box of its own is listed in `INKED` (`web/src/ink.js`): it gets proportional figures and is centred on its ink, measured, never nudged by hand (design canon §2; Okay, 14 Oct 2026); numbers that change in place stay tabular. A control smaller than a row's height goes into the *reach* rule (controls layer), so a finger can press it from just outside its edge. **A change to the stylesheet that must not change the look is proved** with the look-check, `web/test/same.mjs`: save the look before (`node test/same.mjs save`), compare after; it reads the computed style of every element in 447 states and prints every difference. **Special places** (Okay, 16 Oct 2026: "r32 is fine"; special places "may happen sometimes"). A value may leave the scale, or a part the rules above, only as a **special**: a named token in one labelled block of `1-tokens.css` (`/* specials */`), with Okay's words and the date beside it, used by name — never a bare number in a rule. `!important` and negative margins stay banned: there is no special for them. The layout check (#188) will read the block, so anything off the scale that is not in it fails; the block is looked through at each release (how many, still wanted?). The block stands at the end of `:root` in `1-tokens.css` (#290), in two groups: the ones Okay asked for, each with his words, and the ones found off the scale with no figure from him (#294). The grid's own measures (`--margin`, `--eye`, `--gap`, `--col`) and the sizes of things are not specials.
- **R33 · Icons** (canon: `docs/design.md` §9). Every icon is drawn in the icon block at the top of `web/src/app.js`, at the size it is shown (viewBox = size on screen; the hand tiles alone at ×2). Every stroked line uses one of the four widths there, `LINE` 1.5 · `SLANT` 1.5625 · `CURVE` 1.625 · `DENSE` 1.25, chosen by what the line is (straight · slanted · curved · crowded), or a pictured width listed in `web/icons/check.mjs`; a quiet sign (Okay's choice, e.g. the rename box) is `DENSE` with its box's corners `DENSE + 1/8`; a dashed ring ends its dashes square, every other line round; a box with round corners is drawn with `box()`; a `LINE`'s level and upright runs sit on quarter points. Rings, frames and outlines inside an icon are icon lines and weigh the same as the rest; a stylesheet border is never used for a line that is part of a sign. A new or changed icon goes through the pipeline: `web/icons/fit.mjs` (on the grid), `web/icons/check.mjs` (the rules; in `npm test`, must pass), `web/icons/look.py` (how heavy it looks: within 6 % of a straight `LINE`, or a reason), and a look at `web/icons/out/sheet.png`. Okay, 14 Oct 2026: "Let this knowledge of good and proper icon making be canon. This pipeline for upcoming icons."*

## Process

- **R18 · Simplest approach that works** (Occam). No new feature without Okay asking.
- **R19 · Test before handing over — as much as the push needs** (Okay, 19 Oct 2026: "Each .x step up gets the full check … Only filter makes more sense now … Check smartly"). Two sizes of push, two sizes of check:
  - **A small push** (the third number, 4.88 → 4.88.1): the checks the change touches — the window test's sections for the parts changed (`node test/window.mjs --only <sections>`, once #407 lands), the icon check for icons whose drawing changed (`node icons/check.mjs --changed`), the look-check (`same.mjs`) only when the stylesheet changed, and a look at the screenshots of those parts. Code can reach code, so a change in `geometry.js` runs the geometry sections too; icons don't reach each other, so only the changed ones.
  - **A step** (the second number, 4.88 → 4.89): `cd web && npm test` whole — parity with `dial.py`, labels, links, complications, Wear OS, the window, every icon — and `same.mjs` when the look should not have moved; then a look at `web/test/out/sheet.png`, the screenshots and `web/icons/out/sheet.png`. The full check also looks at what a filtered run can't: the panel's distances (#188), pressed and pushed states, popups and lists that overlap other parts. That list is not complete; the point is to check smartly — what the step's changes could have reached — not everything every time.
  - Before a release to `main`: the step's full check, always.
- **R34 · No band-aids: one need, one mechanism** (Okay, 19 Oct 2026: "no band-aid solutions, if new prompt is something new, just check code at how we do similar things, if none exists, make this a new law. Robust, future proof. Remove conflicting laws or edit appropriately"). Before building an ask, find how the tool already does the like (a row form, a heading-line control, a note, a pane) and use that. If nothing does, build it as a mechanism others can use and write it here as a rule; a rule it contradicts is edited or removed in the same push. A condition, a value or a selector written for one place only is the sign to stop and look again.
- **R20 · Third attempt at the same fix → stop and ask.** The first assumption was probably wrong.
- **R21 · Measure, don't estimate** — sizes and timings come from real renders.
- **R25 · The guide follows the app** (`guide/`, by `guide/PLAN.md`). Its pictures are made by script from the current app, never drawn; every "do X and Y happens" sentence has a scripted check that must pass. **It is rebuilt only when Okay asks** (`bash guide/make.sh`; Okay, 16 Oct 2026: "decouple the guide creation from each build, it's hand generated every once in a while by triggered me"): an app release does not touch it, and the live guide names the version it was made on; the picture diff then shows what changed since the last guide. Never type a value into the guide that a picture or a check doesn't use. Page design follows `guide/notes-okay.md` and the design canon (R29).
- **R29 · `docs/design.md` is the design canon** for anything shown that isn't a dial: type, grid, colour, pictures, redrawn controls, writing. Follow it; when a new need doesn't fit, change the canon first, then the page.
