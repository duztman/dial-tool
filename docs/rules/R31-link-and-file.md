# R31 · A dial's link is for sharing a dial now; a settings file is for keeping one

**The address bar stays short** (#537; Okay, 24 Oct 2026: "hide the full address and make the link still work"): a link opens its dial, the dial goes into the session, then the address is cut back to the site's; Copy link gives the whole dial. A link carries only what differs from the starting values (`lean()` in `geometry.js`), packed and written in capitals and digits — link scheme 5 (`LINK_SCHEME`; `LINK_KEYS`, the key table, only grows, at its end, and is checked against `web/test/link-keys.json` by `linktrip.mjs`). **Old links may die** (Okay, 16 Oct 2026: "previous links may die, replace the system"): the starting values (`DEFAULTS`, `RING_BASE`, `HAND_BASE`, `WINDOW_BASE`, the starting rings and hands) may change when a change needs it. Whenever a change would make an existing link draw something else — a starting value, the key table, the alphabet — the scheme number goes up, and a link of another scheme is not read: the tool opens the opener and says, on the preview and in the Export log, that the link was made by an older Dial Tool (R17: no silent dead end, and never a dial quietly drawn wrong). A new key whose starting value draws what was drawn before needs no new scheme. Keys are never renamed (R8), so a settings file, which holds every value, keeps opening. When the scheme changes, everything in the repo kept as a link is written again from its settings (the Gallery: `node gallery.mjs`; the examples: `node examples.mjs`; the opener's link in `opener.js`); the live guide's links die until the guide is rebuilt, on Okay's word only (R25).
