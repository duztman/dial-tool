# R19 · Test before handing over — as much as the push needs

**Test before handing over — as much as the push needs** (Okay, 19 Oct 2026: "Each .x step up gets the full check … Only filter makes more sense now … Check smartly"). Two sizes of push, two sizes of check:
  - **A small push** (the third number, 4.88 → 4.88.1): the checks the change touches — the window test's sections for the parts changed (`node test/window.mjs --only <sections>`, once #407 lands), the icon check for icons whose drawing changed (`node icons/check.mjs --changed`), the look-check (`same.mjs`) only when the stylesheet changed, and a look at the screenshots of those parts. Code can reach code, so a change in `geometry.js` runs the geometry sections too; icons don't reach each other, so only the changed ones.
  - **A step** (the second number, 4.88 → 4.89): `cd web && npm test` whole — parity with `dial.py`, labels, links, complications, Wear OS, the window, every icon — and `same.mjs` when the look should not have moved; then a look at `web/test/out/sheet.png`, the screenshots and `web/icons/out/sheet.png`. The full check also looks at what a filtered run can't: the panel's distances (#188), pressed and pushed states, popups and lists that overlap other parts. That list is not complete; the point is to check smartly — what the step's changes could have reached — not everything every time.
  - Before a release to `main`: the step's full check, always.
  - **Where each goes** (Okay, 21 Oct 2026: "Small updates only on dev … Main gets all the tests"; #500): a small push goes to the /dev/ page (`duztman.github.io/dial-tool/dev/`, `tools/release.sh dev "first line"`), after the quick checks; a step goes to the released page and moves `main` to `dev` (`tools/release.sh 4.92 "first line"`), after the full check. The /dev/ page keeps its own browser storage, so the released page's saved dials and session are never touched.
  - **Numbers** (Okay, 20–21 Oct 2026): a small push counts in the third number, a step in the second, each up to 99. The build released on 27 Oct 2026 is named **v1.0 beta** (Okay: "call this a v1.0 beta version from now on"), and counting goes on from it: v1.0.1 beta, … v1.1 beta. **v1.0**, without "beta", comes on Okay's word, when the build list's v1 section is done; after it, 1.0.1 for a small push and 1.1 for a step. A beta comes before its release (Semantic Versioning), so 1.0 after beta 4.9x is not a step back (Okay: "Yes: v1.0, then 1.0.1 / 1.1").

**Checked by:** `npm run small` (a small push) · `npm test` (a step) · the screenshots in `web/test/out/`
